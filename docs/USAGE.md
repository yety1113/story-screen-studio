# 使用说明

## 安装

在本仓库根目录运行：

```sh
codex plugin marketplace add .
codex plugin add story-screen-studio@story-screen-studio-github
```

安装后开启新任务，让新的技能目录生效。若已经安装同名本地完整版，不必再装此版；不要同时启用两个同名插件，以免技能重名。此发布操作不会替换本地完整版。

## 从灵感开始

告诉 story-studio：题材、面向谁、预计篇幅、已有材料和本次希望完成的内容。不知道的项目可以留空，不必一次填完问卷。

先获得一句话故事、主人公的可执行目标、关键阻力和结局方向。认可后，再细化人物、情节和章节。方案尚未确认时，不要把推测自动写成正式设定。

## 从已有稿件开始

将需要处理的章节放在工作目录，明确是诊断、润色还是重写。story-audit 负责定位主要问题；novel-writing 负责正文层面的叙事与语言。仅请求审核时，不应自动改稿。

## 面向影视改编

让 screen-adaptation 分开评估“小说是否成立”与“改编需要改变什么”。可以交付一句话提案、人物关系、故事梗概、篇章或分集方向、主要制作难点。不要在没有材料时编造行业报价、平台偏好或版权成交概率。

## 推荐提示词

> 使用 story-craft，把这个灵感发展成三个不同的主角困境。比较每种方案的冲突持续性和人物代价，我选择后再写大纲。

> 使用 story-beats，检查大纲中哪些转折来自人物行动，哪些靠偶然推动。不要机械调整到固定百分比。

> 使用 screen-adaptation，判断这部小说更适合电影、剧集还是暂不适合改编。用稿件证据说明，并标注信息不足之处。

## 保存与协作

沿用作者已有目录。需要新建项目时，可使用“设定 / 大纲 / 正文 / 修改记录”四个目录，但应以实际任务为准。正式稿与建议稿分开保存，重要改动说明影响范围。插件不会自动提交、发布或上传作品。
